# MindLoom 单页协同文本内核

纯 Python、零依赖的协同纯文本内核（类 RGA 的字符级 CRDT 变体）。
状态全部驻内存；不保证线程安全、持久化与崩溃恢复；最多 12 个副本。

## API

```python
from mindloom import Replica

r = Replica("A")            # replica_id 唯一且固定，初始内容为空
m1 = r.insert(0, "hello")   # 立即本地生效，返回可 JSON 序列化消息
m2 = r.delete(0, 2)         # 删除可见文本的左闭右开区间
r.receive(m1)               # 接收消息（自己的或他人的），可重复、乱序
r.text()                    # 当前可见文本
```

- 位置按 Unicode 码点计数（Python `str` 语义），非 BMP 字符计 1。
- 本地参数假设合法；每次本地插入/删除的即时结果与字符串切片一致。
- 各副本的 `replica_id` 必须两两可比较（建议统一用 `str` 或统一用 `int`）。

## 消息语义

消息为纯 JSON 可序列化字典，只携带本次增量与定位/因果元数据，不含全文或历史。

- 插入：`{"type": "insert", "chars": [record, ...]}`，每个 record：
  - `id`: `[replica_id, seq]`，字符全局唯一标识（`seq` 为副本内递增计数）；
  - `anchor`: 左邻居字符 id 或 `null`（文首），插入的定位依据；
  - `group` / `within`: 片段排序键（见下）；
  - `ch`: 单字符文本。多字符插入按顺序展开为多条 record，后者锚定前者。
- 删除：`{"type": "delete", "ids": [[replica_id, seq], ...]}`，
  只列出发起时区间内可见字符的 id；删除即墓碑，不物理移除。

接收端语义：

- 重复消息幂等（按字符 id / 删除集合去重）。
- 删除可先于创建到达：先记 id，创建到达时直接落成墓碑。
- 锚点未到的插入记录进入缓冲，不阻塞其他消息；每次有新记录生效后
  重放缓冲直到无进展。副本在只收到部分消息时可继续本地编辑。
- 字符的排序键在创建时固定，后到消息只追加字符，绝不重排已有字符。

## 片段排序规则（不交错保证）

字符组织为锚点树：每个字符挂在 `anchor` 之下，`anchor=null` 表示文首。
同一锚点下的兄弟按 `(group, replica_id, within)` 排序：

1. `group` 大者靠前；
2. `group` 相同，`replica_id` 大者靠前；
3. 再相同，`within` 小者靠前。

可见文本为锚点树的前序遍历（跳过墓碑，但保留其子树）。

新字符的键分配：

- 常规插入：`group = 该锚点下已知最大 group + 1, within = 0`，
  因而落在锚点之后所有已知兄弟之前，保证本地即时位置等于切片语义。
- 向左前插：若右邻居与本新字符同锚点且同属本副本，则并入右邻居的
  `group`，`within` 取该组已知最小值减一。

因此同一副本从同一缝隙出发的连续编辑（向右追加、向左前插或混合）
共享一个 `group`，合并时该片段整体作为兄弟序列中的连续块出现；
两个并发片段的先后由 `(group, replica_id)` 唯一决定，与消息到达
顺序无关。例如“LR”上甲插 `x,y`、乙插 `u,v`（均位置 1），
本实现稳定得到 `LvuyxR`（replica_id 大者的片段在前）。
