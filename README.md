# MindLoom 单页协同文本内核

纯 Python、纯内存的字符级 CRDT 文本内核，不依赖任何现成 CRDT/协同编辑库，
不需要中心排序者、物理时钟或投递顺序保证。

## 用法

```python
from mindloom import TextReplica

a, b = TextReplica("A"), TextReplica("B")   # replica_id 唯一且固定，最多 12 个副本
m1 = a.insert(0, "hello")   # 立即本地生效，返回可 JSON 序列化的消息
b.receive(m1)               # 消息可重复、乱序、延迟投递
m2 = a.delete(0, 1)         # 删除左闭右开区间
b.receive(m2)
assert a.text() == b.text() == "ello"
```

四个操作：`insert(pos, text)`、`delete(start, end)`、`receive(message)`、
`text()`。位置按 Unicode 码点计数；本地插入/删除的即时结果与字符串切片
一致。初始内容也通过 `insert` 产生并分发给其他副本。

## 消息语义

消息只携带本次新增文本、删除目标和定位/因果元数据，可 JSON 序列化：

- 插入：`{"op": "insert", "replica": rid, "seq": n, "text": s,
  "parent": [rid, k] | null, "right": [rid, k] | null}`
  - 每个字符的全局 id 为 `(replica, seq + i)`（`i` 为字符在 `text` 中的下标）。
  - `parent`：插入缝隙左侧相邻字符的 id（遍历序，含墓碑），`null` 表示文档起点。
    首字符挂在 `parent` 下，后续字符依次挂在前一字符下。
  - `right`：插入缝隙右侧相邻字符的 id，`null` 表示文档末尾；仅首字符记录，
    用于兄弟节点间的链式排序（见下）。
- 删除：`{"op": "delete", "targets": [[rid, k], ...]}`，显式列出发起时
  可见区间内每个字符的 id，因此只影响这些字符，不会吞掉并发插入。

接收规则：字符的 `parent` 或 `right` 指向的字符尚未到达时，该字符进入
孤儿缓冲，不阻塞其他依赖已满足的更新；依赖补齐后自动落库。删除目标未
到达时记录为待删，创建消息到达时立即标记。重复投递全部幂等。

## 片段排序规则（稳定，与投递顺序无关）

同一父节点下的子节点按如下规则排序（只依赖消息中的静态元数据）：

1. 若节点 x 的 `right` 也是同一父节点下的子节点，则 x 通过 right 链排在
   该右邻**之前**，形成一条“链”；指向同一右邻的多个节点按
   `(replica_id 升序, 序号降序)` 排列，各自先递归输出自己的前驱子链。
2. `right` 不是同父子节点的节点是链尾；同一 replica 在同一父节点下至多
   一条链尾，链之间按链尾的 `(replica_id 升序, 序号)` 排列。

效果：两个副本从相同状态的同一缝隙出发、互不接收消息、各自只在新增文本
内部或两端继续插入时，合并后每个副本新增的字符各自构成一个连续片段并
保持本地顺序（追加、前插及混合均成立）；**两个片段的先后按 replica_id
升序排列**（如 `A` 的片段在 `B` 之前）。例如初始 `LR`，A 在位置 1 依次
插入 `x`、`y`，B 在位置 1 依次插入 `u`、`v`，唯一结果为 `LyxvuR`。

后到消息只为新字符计算静态位置，绝不重排已有未删字符的相对次序。

## 测试

```bash
python3 -m pytest test_mindloom.py -v
```

覆盖：反向输入示例（4! 种投递排列 + 重复投递）、两端混合插入的片段
连续性、删除先于创建、两侧邻居均已删除的插入、缺失依赖期间的独立更新、
删除不吞并发插入，以及固定随机种子的三副本交错编辑收敛（含重复字符、
非 BMP 字符、部分合流后继续编辑、逐次切片校验）。
